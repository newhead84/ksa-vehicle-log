## 1. 기준
- 최종 갱신: 2026-11-16 · 기준 커밋 `5a7b1b0` (롤백 지점 태그 `v2026.11.16-pre`)

## 1-1. 최근 반영 (2026-11-16)
- 영수증 일자 판정 보완: 첨부 후 운행일을 바꾸면 일자 재판정(운행 입력·내 기록 수정), 저장된 기록의 시작일 변경 시 재계산, 관리자 목록에 읽은 날짜 표시, 관리자 "🔁 다시 판정"(금액·일자·유형, 이전 판정은 `receiptRejudge` 신규 필드에 보관)
- 개인사용 점검 시작일 `PERSONAL_MONITORING_SINCE` = 2026-11-01(11월 이전 건은 처리 대기·문제건 집계 제외, 전체보기로 조회)
- 늦은입력 겹침 관리자 "확인완료"(처리 대기 상세 목록 버튼, `lateEntryCheckedAt` 신규 필드, 겹침 이력 필드는 유지)
- 운영 DB 22건 영수증 일자 판정은 지휘 세션이 별도 갱신 완료(백업은 PC AGENT 폴더)

## 5. 사용자 확인·할 일
- 관리자 화면에서 "🔁 다시 판정"을 1건 눌러 실제 OCR·저장이 되는지 확인(운영 DB 없이 시험 못 함)
- 늦은입력 겹침 3건(181하4792 10-01·10-13, 183호5250 10-22)을 확인해 중복 입력이면 정리하고 "확인완료"로 저장되는지 확인
- 처리 대기의 개인사용 건수가 0건 근처로 줄었는지 확인. 필터는 제출일 기준이라 10월 운행·11월 늦은 제출 건은 남을 수 있음(운행일 기준이 필요하면 `isMonitoredTrip()` 수정)
- Firebase 콘솔에서 `fleet-data/fines` 규칙이 로그인한 사용자 기준인지 확인
- 원하는 것: PC에 매일 자동 DB 백업, 최신 파일 하나만 유지
- 렌터카 계약 갱신은 만료 약 4개월 전부터 준비(입찰 + 신차 출고 기간)
